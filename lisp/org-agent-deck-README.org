#+title: Agent-deck sessions from Org
#+PROPERTY: header-args :eval never-export :tangle no

* Configuration

=ob-agent-deck.el= adds the =agent-deck= Babel language.  The repository's
=init.org= enables it through =org-babel-load-languages=.  For the first load
in an existing Emacs session, evaluate =(require 'ob-agent-deck)= after making this
repository's =lisp/= directory available on =load-path=.

The existing =org-agent-deck-command= controls every launch.  Its default
is intended for Emacs on Clio, with sessions running on Hera:

#+begin_src emacs-lisp
(setq org-agent-deck-command '("ssh" "hera" "agent-deck"))
#+end_src

On Hera itself, local operation uses =(setq org-agent-deck-command
'("agent-deck"))=.  No global Pi model settings are changed.  With SSH, the
first element must be the SSH executable; the configured prefix is trusted,
while launch arguments are quoted for the remote shell and the prompt travels
on standard input.

Hera's =~/.config/agent-deck/config.toml= disables automatic branch prefixes:

#+begin_src toml
[worktree]
branch_prefix = ""
#+end_src

This also removes the default =feature/= prefix from manual worktree launches.

** Reload after updating

Emacs retains loaded function definitions.  Updating a source file or calling
=require= again does not replace those definitions.  Reload both source files
from the checkout that received the update.  For sources loaded from Hera via
TRAMP, evaluate:

#+begin_src emacs-lisp
(let ((directory "/ssh:hera:/Users/johnw/.emacs.d/lisp/"))
  (load-file (expand-file-name "org-agent-deck.el" directory))
  (load-file (expand-file-name "ob-agent-deck.el" directory)))
#+end_src

For local sources, use =~/.config/emacs/lisp/= instead and update that checkout
first.  Explicit =.el= filenames bypass stale bytecode in the current session;
rebuild that checkout's bytecode before restarting Emacs.

* Launch blocks

Place point in a block and press =C-c C-c=.  Normal Org evaluation controls
remain in force.  The body becomes the initial prompt; results contain the
new session ID and launch settings, not the agent's eventual answer.  Emacs
waits for the CLI to start the session and deliver the prompt, but not for
the task to finish.  With =:mailbox=, Emacs waits for delivery of =/mailbox=
instead, and the prompt follows in the background; see [[*Mailbox][Mailbox]].

** Work

#+begin_src agent-deck :preset work :directory ~/src/project :title "Design review"
Review this project's design and suggest next steps.
#+end_src

The work preset selects group =Positron=, harness =claude=, model
=claude-opus-5-5=, and thinking =max=.  It turns on Ultracode only once the
updated Nix claude wrapper (=nix-sko41=) is active on Hera; until then it
says =:ultracode nil=; see
[[*Max effort with Ultracode][Max effort with Ultracode]].  The work-codex preset uses the same group
with harness =pi=, model =openai-codex/gpt-6-astra=, and thinking =max=.

** Max effort with Ultracode

=:ultracode yes= turns on Ultracode: standing dynamic-workflow orchestration
for the whole session.  With =:thinking max= it gives max effort with
Ultracode.  The work preset sets =max=, and will set Ultracode too once the
updated claude wrapper is active; until then, ask for it:

#+begin_src agent-deck :preset work :ultracode yes :directory ~/src/project
Plan and carry out this refactoring.
#+end_src

#+begin_src agent-deck :preset work :ultracode yes :harness codex :model gpt-6-astra :directory ~/src/project
Plan and carry out this refactoring.
#+end_src

- Claude :: The launch passes =--effort= from =:thinking= and the settings
  overlay ={"ultracode":true}= as a Claude argument.  Agent-deck stores that
  argument with the session, so a restart keeps Ultracode.  Only a Nix
  claude wrapper that admits this one overlay lets it through (nix-config
  item =nix-sko41=); an older wrapper refuses every caller =--settings=, and
  the new session ends at once in status =error=.  Until the updated wrapper
  is active on the host that runs the session, a remote included, add
  =:ultracode no= to Claude blocks that use the work preset, or use the
  claude preset.  Claude applies Ultracode only when dynamic workflows are
  enabled and the model supports it; Emacs checks neither.  =:thinking= sets
  the session's effort; workflow agents may still choose lower efforts.
- Codex :: Ultracode is Codex's =ultra= effort, maximum reasoning with
  automatic task delegation, so =:thinking= must be =max=, =default=, =ultra=
  or omitted; a lower effort needs =:ultracode no=.  =:thinking ultra= alone
  is Ultracode too, so it cannot be combined with =:ultracode no=.  Results
  report thinking =ultra=.  Codex 0.167 offers it for gpt-6-astra,
  gpt-6-sol, gpt-6.1-sol, gpt-6.1-terra, gpt-5.6-sol and gpt-5.6-terra, but
  not for gpt-5.5 or the luna models.
- Pi and the other harnesses have no Ultracode, and requesting it is an
  error.  The work-codex preset runs Pi, whose highest level is =max=.  With
  the work preset, add =:ultracode no= before selecting such a harness.

Results add =Requested ultracode: yes=.  =:ultracode no= turns off a preset
or inherited setting.  Headers take only =yes= or =no=: a bare =:ultracode=
is an error, as a bare =:worktree= is.  Presets may also write =t= or =nil=.

** Remote hosts

Add =:remote= to have Hera's agent-deck create the session on one of its
registered remotes instead of on Hera itself:

#+begin_src agent-deck :preset work :remote vulcan :directory ~/src/project
Review this project's design and suggest next steps.
#+end_src

Emacs still reaches Hera through =org-agent-deck-command=.  Hera then runs
=agent-deck remote exec vulcan launch ...=, which streams the prompt to the
remote over SSH standard input.  The value must be a remote name listed by
=agent-deck remote list= on Hera, not an SSH host or =user@host= target.
Everything else resolves on the remote: =:directory= (including =~/=),
worktrees, groups, harnesses, models, and thinking levels.  The harness must
be installed and signed in there, and both hosts need an agent-deck with
remote launch support (=agent-deck remote update vulcan= upgrades the remote).

Results add a =Remote:= line, because the session ID belongs to that remote.
From Hera, inspect the session with =agent-deck remote vulcan show ID= or
attach with =agent-deck remote attach vulcan ID=.  A preset may also set
=:remote=; an explicit header overrides it.  To send later entries to such a
session or read its replies, see [[*Existing sessions][Existing sessions]].

** Titles and worktrees

=:title= is the exact session title, without a UUID suffix.  When omitted, it
defaults to the basename of =:directory= after removing the trailing separator.
For example, both =~/src/project= and =~/src/project/= default to =project=.

Add =:worktree yes= to create a new worktree and branch named after that title:

#+begin_src agent-deck :preset work :directory ~/src/project :title fix-capture :worktree yes
Fix the capture issue in this isolated worktree.
#+end_src

This uses agent-deck's =subdirectory= layout: for an ordinary Git repository,
the session runs in =<repo>/.worktrees/fix-capture= on branch =fix-capture=.
A target-side =path_template= override still takes precedence over the layout.
The title must be a valid Git branch name without spaces or slashes; agent-deck
checks the remaining Git restrictions.  =:worktree no=, or omitting the header,
launches directly in =:directory=.  Results show the actual directory and, for
worktree launches, the branch.

** Mailbox

Add =:mailbox= to have the session join the shared agent-mail mailbox before it
starts work.  The value is the session's mailbox name, optionally followed by
topic specs in the =/mailbox= skill's syntax: =+topic= subscribes quietly,
=++topic= wakes the session, and =!+topic= or =!++topic= also makes the topic a
write target.

#+begin_src agent-deck :preset work :directory ~/src/project :mailbox fix-capture ++nix-config
Fix the capture issue.
#+end_src

Agent-deck starts the session without a prompt.  Emacs then sends
=/mailbox fix-capture ++nix-config= as a command of its own.  It waits up to
10 minutes for the new session to become idle, and until agent-deck sees the
agent take the command up.  The block body follows through
=agent-deck session send --defer-if-busy=, which holds it while the =/mailbox=
turn runs, so the join never absorbs the prompt.  That hold works only while
the session reads busy, so a =/mailbox= that agent-deck delivered without
seeing it taken up is an error, as is an interrupted wait (=C-g=); both name
the new session.  =/mailbox= is not the launch message because launch lacks
the guard =session send= has against Claude reading a slash command as plain
text before registering its commands.

Agent-mail binds a session under its title, so the name must be the title in
lower case; without =:title=, the title defaults to the name.  Names and topics
must also follow agent-mail's naming standard: lower-case letters, digits, =.=
and =-=, starting with a letter or digit, with no =--= and no trailing =-=, at
most 64 characters, and not reserved (such as =all=, =claude=, or =john-=
names).  Emacs refuses anything else before launching, because =/mailbox=
would stop to ask, and the prompt would then arrive as the answer.  Emacs
cannot tell whether another session already uses the name.  If =/mailbox=
stops for that or any other reason, the prompt still follows once the turn
ends, so read the session's =/mailbox= report.

Joining usually takes minutes, so Emacs does not wait for it.  The results add
a =Mailbox:= line with the command sent and =Prompt: pending until /mailbox
finishes=.  Later, a background process reports a message once agent-deck
confirms delivery.  Otherwise it shows a warning, for example after a hold
longer than the 30-minute =--defer-timeout=.  Nothing is retried.  A warning
does not prove the prompt is missing: when only the SSH connection was lost,
the remote send may still deliver it.  Check the session's output before
sending the prompt yourself.  Emacs asks before quitting while a prompt is
pending, because its delivery would go unreported.
Agent-deck sees a Claude turn end through Claude's hooks.  For Pi, it uses its
pi-hooks extension when installed and otherwise reads the pane, which is less
exact.  With =:remote=, both sends go through =agent-deck remote exec=, like
the launch.

** Overrides and inheritance

Explicit headers override =org-agent-deck-presets=.  Standard file and subtree
header inheritance applies; block-local headers take precedence.  In a property
drawer, use =:header-args:agent-deck+:= to extend inherited arguments rather
than replace that property.

#+begin_example
#+PROPERTY: header-args:agent-deck :preset work-codex :directory ~/src/project

#+begin_src agent-deck :group my-sessions :model omlx-hera/GLM-5.3-Flash-oQ4e-mtp :thinking high
Explain the design without changing files.
#+end_src
#+end_example

A native harness can be selected explicitly.  For example, use the target
CLI's Codex model and reasoning-effort options instead of Pi's options.  The
work preset's Ultracode runs Codex only at maximum reasoning, so a lower
effort also needs =:ultracode no=:

#+begin_src agent-deck :preset work :directory ~/src/project :harness codex :model gpt-6-astra :thinking high :ultracode no
Review this design without changing files.
#+end_src

=:thinking default= clears an inherited thinking override.  Without a preset,
provide at least =:group= and =:directory=; the harness defaults to =pi= and
omitted model/thinking values use that harness's defaults.

* Existing sessions

=M-x org-agent-deck-send-entry= sends the current Org entry and its subtree,
as Markdown, to a running session.  =M-x org-agent-deck-insert-latest-output=
inserts a session's latest reply as a sibling =NOTE= entry, converted to Org
with Pandoc.  Both offer Hera's active sessions to choose from.

With a prefix argument (=C-u=), either command first asks for one of Hera's
agent-deck remotes, such as =vulcan=, then offers that remote's active
sessions.  Listing, sending and reading run through
=agent-deck remote exec vulcan ...=, the route =:remote= launches take, so a
session started by a =:remote vulcan= block can take later entries and return
its replies.

* Header reference and limits

| Header       | Meaning                                                  |
|--------------+----------------------------------------------------------|
| =:preset=    | =work=, =work-codex=, =claude=, or =local=; customizable in =org-agent-deck-presets= |
| =:remote=    | Agent-deck remote that hosts the session, such as =vulcan=; default Hera |
| =:directory= | Required target-host path: absolute or beginning with =~/= |
| =:group=     | Agent-deck group path, such as =Positron= or =my-sessions= |
| =:harness=   | Tool name, not an arbitrary shell command                 |
| =:model=     | Model ID; not a shell expression or glob                  |
| =:thinking=  | Pi thinking level, native CLI effort, or =default=         |
| =:ultracode= | =yes= or =no=: Ultracode for Claude or Codex; the work preset will say =yes= once =nix-sko41= is active |
| =:title=     | Exact title; defaults to the basename of =:directory=      |
| =:worktree=  | =yes= creates a new worktree and branch named =:title=; default =no= |
| =:mailbox=   | =NAME [TOPICS]=: run =/mailbox NAME [TOPICS]= before the prompt     |

Directory paths are never expanded or checked on Clio.  Use =:directory=,
not Babel's =:dir=, which refers to Emacs's working directory.  Spaces,
Unicode, and quotes are preserved; quote header values containing spaces.
The prompt retains its interior line breaks.  Agent-deck removes trailing
line endings before delivery.

Each successful execution creates a standalone session.  Duplicate titles at
the same location, existing branches, or existing worktree paths produce CLI
errors instead of silently renaming or reusing them.  Choose a different title
when another session or worktree already occupies the requested name.
=:session= reuse and =:cache yes= are rejected.  Loading the module never
launches a session; export does not launch, even with an explicit =:eval yes= override.

Pi model and thinking flags are passed through agent-deck's native wrapper
mechanism.  Other harnesses use the target CLI's =--model= and =--effort=
capabilities; unsupported combinations produce CLI errors.  This integration
does not install models, manage credentials, or bypass project trust prompts.

The results label model, thinking and Ultracode values as /requested/, not
independently verified runtime state.  Pi may resolve partial model IDs, accept unregistered
IDs, or adjust a thinking level to the model's capabilities.  The supplied
presets have been verified end to end.  The work preset's Claude Ultracode was
verified through agent-deck, across a session restart, with the updated Nix
claude wrapper built but not yet activated; its Codex variant reached Codex as
=model_reasoning_effort=ultra=.  Arbitrary Pi overrides deliberately
use Pi's own model resolution and thinking normalization.  No target-side
preflight or startup guard is installed.

On a launch error, inspect agent-deck before executing again: a session may
already have been created before startup or prompt delivery failed.  Worktree
creation also creates Git state before launching the agent; a later failure
can leave that worktree and branch in place.  Inspect both before retrying.  Invalid
JSON, missing IDs, queued sessions, and unconfirmed prompt delivery are errors,
not successful results.  There is no automatic retry or removal.  A queued
session requires inspection because the CLI has not confirmed prompt delivery.

* Verification

Run the focused regression suite and byte-compile the changed modules.
=load-prefer-newer= keeps the suite from loading stale bytecode:

#+begin_src sh
emacs --batch -Q -L . --eval '(setq load-prefer-newer t)' \
  -l org-agent-deck-test.el -f ert-run-tests-batch-and-exit
emacs --batch -Q -L . --eval '(setq byte-compile-error-on-warn t)' \
  -f batch-byte-compile org-agent-deck.el ob-agent-deck.el
#+end_src

The suite includes a local SSH-shell emulator and a fake agent-deck for the
=:mailbox= sequence, so these tests require no network connection.  Live launch checks remain necessary for the installed
agent-deck and Pi versions, provider availability, and target permissions.
